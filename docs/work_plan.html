1. What the project is

Why OpenAQ

  • Strong daily, weekly and yearly seasonality, which is ideal for showing SARIMA vs Prophet.
  • Real anomalies (pollution episodes, fireworks, sensor faults, flat-lines) give the anomaly section a story.
  • Proposed scope: one Paris station, PM2.5, hourly readings resampled to daily means, about 2 to 3 years. Data comes from the public OpenAQ S3 archive (s3://openaq-data-archive, no key needed) or API v3 (free key).

Phase 1: Data exploration Prem

  • Plot the full series, a zoomed month, and a rolling mean and std
  • Count missing timestamps; justify the imputation choice (interpolation vs forward fill)
  • ADF test on the raw and differenced series and report the p-values
  • ACF and PACF plots, noting the lags that suggest the p, q and seasonal orders

Phase 2: Decomposition Prem

  • Classical seasonal_decompose (additive vs multiplicative, period = 7)
  • STL decomposition (robust = True)
  • Written interpretation of the trend, seasonality and residuals, and how classical and STL differ
  • Hand the suggested SARIMA orders to Yahya

Phase 3: Initial forecasting Yahya

  • Train/test split by time (last 60 to 90 days as test); no shuffling
  • SARIMA: order selection (ACF/PACF plus a small grid search or auto_arima), residual diagnostics
  • Prophet with weekly and yearly seasonality and French holidays
  • Metrics table: RMSE, MAE (both models), AIC and BIC (SARIMA)
  • Forecast vs actual plot with confidence intervals

Phase 4: Anomaly detection Vishal

  • Statistical method 1: rolling Z-score on the STL residuals
  • Statistical method 2: SARIMA residuals beyond 3 sigma (use Yahya's fitted model)
  • ML method: Isolation Forest or LOF on lag and rolling features
  • (Optional) LSTM autoencoder reconstruction error
  • Plot anomalies on the series; overlap table showing which methods agree
  • Discuss real-world causes (match dates to known pollution episodes or holidays)

Phase 5: Re-forecasting after cleaning Rayyan Yahya

  • Replace the agreed anomalies (interpolation or STL-based imputation)
  • Refit SARIMA and Prophet on the cleaned training data
  • Before vs after comparison table (RMSE, MAE, AIC, BIC) and a written conclusion

Phase 6: Repo and slides All

  • README: problem, dataset and link, how to run, results summary, team Rayyan
  • Notebook runs top to bottom without errors; figures saved to reports/figures/ Rayyan
  • Slides: dataset overview Rayyan, decomposition and stationarity Prem, ARIMA vs Prophet Yahya, anomalies Vishal, insights and recommendations All
  • Dry run of the full presentation with timing All

4. How we work

  • Branches: one per person (prem/eda, yahya/forecast, vishal/anomaly, rayyan/pipeline). Open a pull request into main; one other member reviews it.
  • Notebooks: one per section (01_eda.ipynb, 02_decomposition.ipynb, 03_forecasting.ipynb, 04_anomalies.ipynb, 05_reforecast.ipynb), merged into the final notebook at the end. This avoids notebook merge conflicts.
  • Shared code lives in src/ (loading, metrics, plotting), so everyone uses the same split and metrics.
  • Fixed split: everyone imports the train/test split from src/load_data.py. Never re-split by hand.
  • Progress: the monitoring agent checks the repo against this checklist and posts a status summary. Tick items by merging PRs.
